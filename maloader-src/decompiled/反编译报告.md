## 三、可还原 / 不可还原

| 部分 | 嵌入方式 | 可否还原 | 结论 |
|---|---|---|---|
| `assets/loader.cpp` | `include_str!` **明文** | ✅ 逐字节 | 已还原，与源一致 |
| `dist/*.png`（不可再压） | 原样嵌入 | ✅ 逐字节 | 已还原 |
| `icons/library/*.ico` | 原样嵌入 | ✅ 逐字节 | 已还原 |
| `dist/*.html/.css/.js`、可压 png | **brotli 压缩**后嵌入 | ⚠️ 需解压 | 见下 |
| `main.rs`（Rust 后端） | 编译成机器码 | ❌ | 无法还原源码 |
| `Info.plist` | 生成的 plist | ✅ | 已还原 |

**关于 brotli 前端**：每个文件被压成
`$OUT_DIR/tauri-codegen-assets/<sha256>.<ext>` 再 `include_bytes!`。
这些流无魔数、也无文件名表，从成品二进制里**无法可靠逐个识别**。
正确的还原姿势不是反编译，而是**重建**：
`cargo tauri build` 时它们以明文落在
`src-tauri/target/release/build/macloader-*/out/tauri-codegen-assets/`，
用 `brotli -d` 解压即得原文。本仓库 `dist/` 就是逐字节与此比对一致后的副本。

## 四、关键结论：源码可 100% 复现同一二进制

`src-tauri/` 里的源码用 `cargo tauri build` 构建后，产物与参考产物
**逐字节相同**：

```
Contents/Info.plist              OK  (== 7e789a1c…)
Contents/MacOS/macloader         OK  (== d9e5ef2c…)
Contents/Resources/MacLoader.icns OK  (== c12d8646…)
```

即：这份源码就是参考 `.app` 的确切来源。

### 踩过的坑（写下来免得再踩）

1. **`make_app.sh` 组装的 `.app` ≠ 参考产物。**
   参考产物是 `cargo tauri build` 直接出的**完整 bundle**，而 `make_app.sh`
   手写 Info.plist 并手工组装，两者不一致：
   - 参考：`CFBundleExecutable = macloader`（小写，= Rust target 名）
     `CFBundleIconFile = MacLoader.icns`，`LSMinimumSystemVersion = 10.13`
   - `make_app.sh`：`MacLoader` / `AppIcon` / `11.0`，且无
     `CFBundleDevelopmentRegion / CSResourcesFileMapped / LSRequiresCarbon`
   → 想复现参考产物，用 `cargo tauri build`，不要用 `make_app.sh` 的组装段。

2. **`dist/.DS_Store` 会被嵌进二进制！**
   tauri-codegen（v2.7.1）按 `frontendDist` **递归**收录 `dist/` 下的文件，
   包括 `.DS_Store`（本机 8196 字节）。参考产物的 `dist/` 里就有它，
   所以二进制里含其 brotli 流。删掉它 → 二进制 `__text` 段少 16 字节、
   整体哈希改变（实测 `d9e5ef2c` → `314f3bf8`）。
   **复现时务必保留参考产物当时的 `dist/` 全部内容。**

3. **构建可复现且与绝对路径无关。**
   `/tmp/xA`、`/tmp/xB` 两个**不同名字**的目录、相同内容 → 同样得到
   `d9e5ef2c`。所以二进制哈希只取决于「源码 + 资源内容」，不取决于放在哪。

## 五、其它发现

- **`invalid PE checksum`（生成 exe 时）**：`main.rs` 的 `patch_pe_timestamp`
  改了 PE 时间戳却没重算校验和。签名版会因为 `osslsigncode` 重算而正常，
  未签名版会带一个失效校验和。
- **证书缓存**：`ensure_cert` 曾无条件复用 `~/.macloader/codesign.pfx`，
  导致换图标预设（如 `lib:notepad`）后签名者仍停留在旧主题。修法：
  按主题（`resolve_subject`）缓存并在不匹配时重生成。**此修复会改变产物哈希**
  （多了约 144 字节逻辑），因此参考产物里**不含**该修复 —— 复现参考产物时
  应使用**未加此修复**的 `main.rs`（本仓库即为此版本）。
