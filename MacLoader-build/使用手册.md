## 1. 快速上手

### 首次启动

第一次打开会弹出「缺少编译环境」引导页。生成 Windows exe 需要交叉编译器，点「一键安装」即可（通过 Homebrew，约 1.4 GB）。

| 依赖 | 用途 | 必需 |
|---|---|---|
| `mingw-w64` | Windows 交叉编译器（含 x64 / x86 / windres） | ✅ 必需 |
| `osslsigncode` | Authenticode 签名与时间戳 | 可选（不装则跳签名） |

没有 Homebrew 的话，引导页会给出安装命令，装完点「重新检测」。

### 最短路径生成一个 exe

1. 左侧「C2 免杀」→ 载荷卡片 → **浏览** 选一个 `.bin`（shellcode）
2. 顶栏 **生成 exe**
3. 右侧日志抽屉会展开显示完整过程，底部摘要显示当前配置

## 3. C2 免杀（Windows PE 生成）

### 3.1 载荷

| 项 | 说明 |
|---|---|
| **有效载荷** | shellcode 文件。支持原始二进制、`\xNN` 形式的 C 源码、`0xNN` 数组、纯 hex 文本 |
| **输出文件名** | 默认 `loader.exe`，不写 `.exe` 会自动补上 |
| **输出目录** | 留空 = 当前目录 |

### 3.2 目标

| 项 | 取值 | 说明 |
|---|---|---|
| **架构** | `x64` / `x86` | 目标 Windows 位数 |
| **窗口** | 无黑框 / 控制台 | 「无黑框」用 `-mwindows`，双击不弹控制台；调试时选控制台能看到日志 |
| **内存保护** | `RX`（默认）/ `auto` / `RWX` | 见下 |

**内存保护怎么选：**

- **RX（仅 RX）**：最干净。分配时 RW、解密后翻成 RX。默认选这个。
- **auto**：先按 RX 跑，注册 VEH 捕获写违规再就地升 RWX。适合**自解密载荷**（如部分加密的 shellcode）。
- **RWX**：直接以 RWX 执行。注：**RWX 内存几乎是必杀项**，除非你的载荷确实需要自写，否则别开。

### 3.3 编码与执行

**编码形态**（决定 payload 在 exe 里以什么形式存在）：

| 形态 | 说明 | 备注 |
|---|---|---|
| `chunk` 分块变密钥 | 切成 3-7 块，每块独立 XOR 密钥 | **实测通过 360 + 火绒**，默认 |
| `b32` Base32 字母表 | 乱序自定义字母表的 Base32 | 实测通过 |
| `chunk_r` 分块+随机倒序 | 部分块倒序存放 | ⚠ 实测被 360 杀 |
| `auto` 自动 | 在 chunk / chunk_r 里随机挑 | 形态不确定 |
| `b64` Base64 分段 | 切成长度随机的小段 | ⚠ 实测被 360 杀 |
| `uuid` UUID + XOR | 每 16 字节编成 UUID 串 | ⚠ 实测被 360 杀 |
| `raw` 明文数组 | 直接 hex 数组 | ⚠ 实测被 360 杀 |

选中被查杀的形态时，卡片内会出现橙色警告条，**不阻止你选择**（做对照实验时需要），但底部摘要会标橙。

**执行方式**：

- `direct`：直接调用（**实测通过 360**，默认）
- `fiber`： fiber 切换执行 ⚠ 实测被杀
- `callback`：回调执行 ⚠ 实测被杀

**两个复选框**：

- **编译期代码随机化**：额外生成一个垃圾翻译单元（随机命名函数 + 构造期调用 + 随机数据块），改变二进制形态与布局，不参与逻辑。**每次构建都不同**，这是产物哈希变化的主因。
- **反分析严格模式**：检测到调试器 / 低内存 / 单核时**退出**而非仅记录。默认关（关了才会在沙箱里照跑，便于观察）。

### 3.4 图标

内置 7 个图标（notepad / word / excel / ppt / pdf / pdf-2 / pdf-3），也支持自定义 `.ico / .png / .jpg`。

**关键点：图标会联动另外两处身份**——

- 选 `lib:notepad` → VERSIONINFO 写 `CompanyName = Microsoft Corporation`
- 同时证书主题自动生成 `/C=US/O=Microsoft Corporation/CN=Notepad`

三者（图标 / 版本信息 / 签名者）必须自洽，否则等于自证伪造。**换图标会自动换证书**，不需要手动干预。

### 3.5 资源与签名

| 项 | 说明 |
|---|---|
| **完整资源伪装** | 写入 VERSIONINFO（厂商 / 产品名 / 版本号）+ 应用清单（RT_MANIFEST）。不开的话 exe 没有版本信息，静态特征很突兀 |
| **Authenticode 自签名** | 用自签证书签名，默认开。会打时间戳 |
| **证书主题** | 留空 = 按图标自动推导。要自定义就填 `/C=US/O=xxx/CN=xxx` 形式 |

> 时间戳服务器固定使用内置值，不再占用界面空间。

### 3.6 诱饵文档

选一个 PDF 会作为 `RCDATA` 嵌进 exe 资源里。运行时**先释放到 %TEMP% 并用默认程序打开**，用户看到的立刻是这份 PDF，之后才轮到 payload。选了 PDF 会自动把图标切成 PDF 图标。

### 3.7 元数据与加载

| 项 | 说明 |
|---|---|
| **创建时间伪造** | `随机`（近两年内随机）/ `指定时间` / `不修改`。会同时改写 PE 头 TimeDateStamp、Debug 目录时间戳、文件 mtime/atime |
| **加载方式** | `本地内嵌`（payload 编进 exe）/ `远程 URL`（exe 里只放 URL，运行时下载） |

**远程模式**会额外产出一个 `<名字>.payload` 文件，把它上传到你的 C2 即可。运行时 exe 会自动下载并 XOR 解密后执行。也支持在 exe 同目录放一个 `payload.url` 文本文件临时改地址，不用重新生成。

### 3.8 实测预设

C2 视图顶部的分段控件，一键套用实测通过的组合：

| 预设 | 编码 | 执行 | 保护 | 图标 |
|---|---|---|---|---|
| 标准组 | chunk | direct | RX | notepad |
| b32 | b32 | direct | RX | notepad |
| prot_auto | chunk | direct | auto | notepad |
| prot_rwx | chunk | direct | RWX | notepad |

## 4. 变体矩阵

一次生成多个样本，**每个相对基线只改一处**。拿到实测结果后能直接归因到那个变量——而不是"一次改一堆，过了不知道是谁的功劳，杀了不知道是谁的锅"。

分两个子页：**C2 矩阵** 与 **Webshell 矩阵**。

### 4.1 C2 矩阵

| 项 | 说明 |
|---|---|
| **Payload** | 矩阵专用，可指定独立的 `.bin / .raw / .c / .txt`，不用沿用 C2 页那份 |
| **输出目录** | 留空则沿用 C2 页的输出目录 |
| **沿用当前 C2 配置** | 把 C2 页的配置（含 payload）带过来当基线 |

点顶栏 **生成矩阵**，会生成 16 个变体：

| 变体 | 改了什么 |
|---|---|
| `base` | 基线（完全按当前配置） |
| `enc_uuid` / `enc_b64` / `enc_b32` / `enc_chunk_r` / `enc_raw` | 只改编码形态 |
| `no_obf` | 只关代码随机化 |
| `mode_fiber` / `mode_callback` | 只改执行方式 |
| `prot_rwx` / `prot_auto` | 只改内存保护 |
| `no_res` | 只去掉版本信息/清单 |
| `no_icon` | 只去掉图标 |
| `no_sign` | 只关签名 |
| `anti_strict` | 只开反分析严格模式 |
| `console` | 只改控制台版 |

结果表格里每行有 **360 / 火绒 / Defender** 三个输入框，实测后直接填 `过` 或 `杀`。「显示」按钮在 Finder 里定位该产物。

### 4.2 Webshell 矩阵

对**同一种语言**穷举不同变换组合，用来判断哪个变换引起被杀。

选语言 → 选输出目录 → 点 **生成 Webshell 矩阵**，生成 10 个变体：

`base`（全开）· `no_rename` · `no_junk` · `no_split` · `enc_xor_only` · `enc_b64_only` · `enc_rev` · `enc_chunk` · `enc_none` · `plain`（全关）

## 5. Webshell 免杀

### 5.1 支持的语言

| 语言 | 运行环境 | 验证状态 |
|---|---|---|
| **PHP** | PHP 5.6+ / 7.x / 8.x | ✅ 已在 PHP 8.2 与 7.4 上实际执行成功 |
| **ASP**（经典 VBScript） | IIS | ⚠ 静态结构校验通过（Linux 无 VBScript 引擎，无法真跑） |
| **ASPX**（C#） | IIS / .NET | ✅ C# 代码已用 mono 编译通过（真跑需 Windows IIS） |
| **JSP**（Java） | Tomcat | ✅ 已在 Tomcat 9 / JDK 17 上实际执行成功 |

### 5.2 基本设置

| 项 | 说明 |
|---|---|
| **语言** | PHP / ASP / ASPX / JSP |
| **载荷类型** | 见下，会**按语言自动过滤**不支持的项 |
| **连接参数名** | 例如填 `pass`，运行时用 `?pass=命令` 传参 |
| **Shellcode** | 只在选 shellcode 类型时出现，填十六进制 |

**载荷类型**（随语言变化）：

| 类型 | 说明 | PHP | ASP | ASPX | JSP |
|---|---|:-:|:-:|:-:|:-:|
| `sh` `/bin/sh` 命令回显 | Linux Tomcat 用 | — | — | — | ✅ |
| `exec` 命令执行（不回显） | | ✅ | ✅ | ✅ | ✅ |
| `cmd` 命令回显 | Windows cmd.exe 版 | ✅ | ✅ | ✅ | ✅ |
| `eval` 代码执行 | | ✅ | ✅ | 降级 | 降级 |
| `shellcode` | 十六进制 shellcode | ✅ | ❌ 不支持 | 仅还原 | 仅还原 |

> **ASP 不支持 shellcode**：VBScript 的 `ChrW()` 返回受当前代码页影响的字符，二进制不安全。
> **ASPX / JSP 的 shellcode 只做字节还原**：直接执行需要 VirtualAlloc / JNI，静态特征极重。

### 5.3 编码链

按顺序套用，可多选：

| 编码 | 说明 |
|---|---|
| **XOR 单字节** | 随机密钥（1-254，避开 0）逐字节异或 |
| **Base64** | 标准 Base64 |
| **字节逆序** | 整体反转 |
| **分块插桩** | 每 3 字节插一个随机分隔符字节，运行时剔除 |

> ASP 经典没有内置 Base64 解码，勾了会自动跳过并在日志里说明。

### 5.4 混淆变换

| 项 | 说明 |
|---|---|
| **变量名随机化** | 把 `d` / `o` / 函数名换成随机名（会避开各语言保留字） |
| **插入垃圾代码与注释** | 随机注释行 + 永不执行的 `if (false)` 分支 |
| **字符串拆分拼接** | 把长串切成随机长度片段，运行时拼起来——避免超长连续串被扫到 |

### 5.5 输出与预览

填文件名（不写扩展名会按语言自动补 `.php` / `.asp` / `.aspx` / `.jsp`）与目录，点顶栏 **生成 webshell**。生成后左下「预览」框直接显示内容，可复制。

### 5.6 混淆已有脚本（保功能）

> **这是最常用的模式**：你已经有一份能跑的 webshell，只想让它绕过上传时的 WAF 检测。

在 Webshell 页顶部选 **「混淆已有脚本」** 模式。

| 项 | 说明 |
|---|---|
| **待混淆的脚本** | 浏览选择你的 `.php / .asp / .aspx / .jsp` |
| **语言** | 按文件类型选 |
| **混淆强度 → 整体编码** | 勾上后原文会被编码，文件里看不到原始代码 |
| **剥离原有注释** | 去掉作者留下的特征串与注释 |
| **插入垃圾代码与注释** | 加随机注释 + 永不执行的分支 |
| **字符串拆分拼接** | 把长串切碎，避免被静态规则匹配 |
| **变量名随机化** | 重命名变量（避开各语言保留字） |
| **输出文件名** | 留空 = 原名 + `_obf` |

点顶栏 **开始混淆**。

**两种强度的区别：**

| | 整体编码（仅 PHP） | 字符串变换（全部语言） |
|---|---|---|
| 原理 | 原文编码后运行时 `eval` | 只改外观，不动语义 |
| 原文可见性 | **文件里完全看不到** | 代码结构仍在 |
| 混淆强度 | 高 | 中 |
| 适用 | PHP | PHP / ASP / ASPX / JSP |

> 非 PHP 语言**没有运行时 eval**（编译型语言），无法整体编码，
> 会自动降级为「字符串变换」并在日志里说明。功能不受影响。

**保功能保证：**

生成器会做这几件事来确保混淆后与原来完全一样：

1. 剥掉源码自带的 `<?php` / `?>`（eval 内不需要，留着反而会解析失败）
2. 剥掉用户脚本已有的 `<% %>` 再统一包回，避免**嵌套标记**
3. 不引入任何新的执行语义 —— 你原来的逻辑原样运行
4. ASP/ASPX/JSP 只做注释剥离、垃圾插入、字符串混淆，不改语句

回归验证脚本会自动比对「混淆前」与「混淆后」的实际命令输出是否一致。

### 5.7 验证脚本

```bash
./tools/ws_docker_test.sh vps
```

会在服务器上用真实环境跑一遍：PHP 8.2 / 7.4 的 `php -l` 与实际命令执行、Tomcat 上 JSP 实际执行、mono 编译 ASPX、ASP 静态结构配对检查。

## 6. 产物自审

对生成的 exe 做**纯静态检查**（不联网、不上传、不执行），把"一眼就能被判死"的特征挑出来。

选一个 exe（或用「浏览」按钮，或直接生成后自动填入），点 **检查**。

**检查项：**

| 维度 | 说明 | 判定 |
|---|---|---|
| 目标架构 | 确认是 Windows PE 及位数 | — |
| 节表熵值 | >7.2 视为高熵（加密/压缩载荷特征） | 高熵警告 |
| RWX 节 | 同时可写可执行的节 | **致命** |
| 节表结构 | 节数 <3 偏异常 | 警告 |
| 资源伪装 | 是否有 .rsrc（图标/版本信息） | 无则警告 |
| Authenticode 签名 | 是否有证书表 | 无则警告 |
| PE 时间戳 | 是否为 0 或过早 | 警告 |
| 产物体积 | >3 MB 偏大 | 警告 |
| 可疑注入字符串 | 明文 `VirtualAlloc` 等 | 警告 |
| 长串载荷痕迹 | 连续 base64/hex 串 >200 字节 | 警告 |

顶部给出 **0-100 分**（pass 项占比）。每条警告都带修复建议。

> 命中不等于一定被杀，但每一项都是静态引擎真实会看的维度。自审只是**自查**，不能替代实测。

## 8. 命令行用法

GUI 之外提供无界面模式，便于批量与自动化。

```bash
# PE 构建
macloader --cli --payload p.bin --out-dir out --encoding chunk --icon lib:pdf

# 变体矩阵（16 个只差一个变量的 exe）
macloader --cli --payload p.bin --out-dir out --matrix

# Webshell
macloader --cli --ws --ws-password pass --out-dir out --name shell.php
macloader --cli --ws --ws-lang jsp --ws-kind sh --out-dir out

# 静态自审
macloader --cli --inspect out/loader.exe
```

**未知参数会直接报错退出**，不会静默忽略后按默认值出文件。

主要参数：

```
--payload <文件>       payload（必填）
--out-dir <目录>       输出目录（默认 .）
--name <名称>          输出文件名（默认 loader.exe）
--arch x64|x86
--encoding auto|uuid|b64|b32|chunk|chunk_r|raw
--mode direct|fiber|callback
--protect rx|rwx|auto
--load embed|remote    --url <URL>
--time none|custom|random   --time-value 2024-03-01T10:30
--icon lib:notepad|路径
--decoy x.pdf
--harden unhook,etw,indirect,stomp,diskssn   --stomp-dll <名>
--cert-subj <主题>
--key 0x41             指定 XOR 密钥
--no-sign / --no-obf / --no-res / --no-errors / --console / --anti-strict
--matrix / --inspect <exe>
--ws --ws-lang php|asp|aspx|jsp --ws-password <名> [--ws-kind ...] [--ws-hex ...] [--ws-enc xor,b64]
```

## 9. 可复现构建

默认每次构建都在随机化块数 / 块长 / 密钥 / 垃圾代码，于是"同一配置"的两次产物哈希不同——**做对照实验时无法判断某个变体被杀到底是因为配置项，还是纯粹运气**。

设置环境变量固定随机序列：

```bash
MACLOADER_SEED=42 macloader --cli --payload p.bin --out-dir out --name a.exe
MACLOADER_SEED=42 macloader --cli --payload p.bin --out-dir out --name b.exe
# a.exe 与 b.exe 逐字节相同
```

另外 `MACLOADER_KEEP=1` 会保留中间源码目录（日志里会打印路径），便于排查生成问题。

## 10. 常见问题

**Q：为什么两次生成同一配置，哈希不一样？**

编译期代码随机化每次生成不同的垃圾代码，且块数/块长/密钥也随机。用 `MACLOADER_SEED` 固定即可（见上）。

**Q：选了某个编码/执行方式，界面变橙了，还能用吗？**

能用，只是**实测被 360 查杀**（判定依据：360 会直接删文件，目录里消失的变体即被杀）。做对照实验时故意选它才有意义。

**Q：生成的 exe 双击没反应？**

- 选的是「无黑框」模式且 payload 执行失败 → 改成「控制台」模式重生成，能看到日志
- 远程模式检查 URL 是否可达，返回内容首字节会被校验（`<` 或 `HTTP` 开头会拒绝）

**Q：换图标后签名者还是旧的？**

不会。证书按主题缓存，换图标会自动换证书。若你手动填过「证书主题」，则以你填的为准。

**Q：构建报 `failed to read plugin permissions` 且路径指向旧目录？**

`target/` 缓存了构建脚本的绝对路径（本目录改名过）。清掉重来：

```bash
rm -rf src-tauri/target/release/build/tauri-* \
       src-tauri/target/release/build/tauri-plugin-* \
       src-tauri/target/release/build/tauri-runtime-*
cd src-tauri && cargo tauri build
```

**Q：怎么确认产物和我改的前端一致？**

```bash
./tools/verify.sh
```

会校验 `dist/` 里的 index.html / style.css / app.js / shell.js 是否逐字节嵌进了 `.app`，并检查 `dist/` 有没有混进临时文件、版本号是否一致。

**Q：关于页显示的版本和 Cargo.toml 不一致？**

版本号从 `Cargo.toml` 读到，显示在关于页；`tauri.conf.json` 里那份用于 bundle。`verify.sh` 会检查两者一致。
